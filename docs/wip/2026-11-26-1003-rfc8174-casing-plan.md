# #1003 — `modal-keywords.casing: rfc8174` (plan)

Issue: driftsys/markspec#1003. Branch `feat/1003-rfc8174-casing`, one PR.

## Decisions (user, 2026-11-26)

- The new value is named `rfc8174`.
- Under `rfc8174`, `markspec fmt` uppercases `shall` and `must` in entry bodies
  (with a following `not`, as the default pass treats `SHALL NOT`), and keeps
  `may`, `should`, `will` and EARS keywords as written. Under RFC 8174 a
  lowercase `may` or `will` is plain English, so rewriting those would create a
  requirement the author never wrote; `shall` and `must` are almost never plain
  English. Inline code keeps any word as written. (User decision, second
  revision, 2026-11-26; replaces "fmt keeps all casing".)
- Under `rfc8174`, MSL-M060 is not emitted, and a lowercase modal keyword in a
  Requirement entry is a new info-level diagnostic, MSL-M062.
- `rfc2119` and `iso` stay aliases of the default (lowercase); documented, no
  code change.
- EARS keywords are not changed by `rfc8174`.
- MSL-Q500 skips modal and EARS keywords under every casing value.
- Task 1's "fmt keeps casing" was superseded by task 5: under `rfc8174`, fmt
  uppercases `shall` and `must`.

## Tasks

Each task: TDD, `just build` green, one commit, then a task review of the task
diff before the next task starts.

1. **Accept `rfc8174`; fmt keeps casing.** Profile validation accepts `rfc8174`
   (`core/profile/manifest.ts`). Every fmt path that keeps keyword casing under
   `preserve` (fmt, check drift gate MSL-F010, LSP formatting, MarkDesk
   proposals) does the same under `rfc8174`, through one shared helper.
   Acceptance: `fmt` keeps `shall` and `SHALL` as written; `fmt
   --check` and
   `check` report no MSL-F010; default, `rfc2119`, `iso`, `preserve` unchanged.
2. **MSL-M062.** `core/validator/modal_keywords.ts`: under `rfc8174`, no
   MSL-M060, and each lowercase modal token in a Requirement entry is MSL-M062
   (info). Add MSL-M062 to the diagnostic catalogue in `language.md` (Part 8;
   M062 is described in §9.1, not Part 8) and to any code list or
   skill/diagnostic doc that enumerates M0xx codes.
3. **Q500 skips keywords.** `core/lint/rules/xref.ts` (and glossary helpers):
   modal and EARS keywords are never reported as undefined glossary terms, under
   any casing value.
4. **Docs and multi-project e2e.** `language.md` (the "All formatting rules are
   fixed." sentence and the #991 paragraph: M060 fires on uppercase, mention
   MarkDesk proposals, describe `rfc8174`, `rfc2119` / `iso` aliases),
   `annex-profile-schema.md` §B.8, ADR-029 (values a project can change),
   `markspec-core-data-model.md` (modal keywords always lowercased, M060
   "normalized by fmt"). E2E test: one `fmt` and one `check` run over several
   projects with different `modal-keywords.casing` values.

5. **fmt uppercases `shall` and `must` under `rfc8174`.** Give the body
   normalization a mode that uppercases only `shall`/`must` (and a following
   `not`), leaves the other modal and EARS keywords unchanged, and keeps the
   #1018 verbatim-inline protection. `keepsModalCasing` splits: `preserve` keeps
   all casing, `rfc8174` uses the new mode. All four fmt paths, tests as in
   task 1.

Then `/review` pass 1 on the PR, fixes, pass 2, merge on the user's go.
