# Issue #843: desk revalidation test gaps and cleanups

Epic: #826. Source: review passes of PR #841 (#833). Branch:
`fix/desk-revalidation-gaps-843`.

## Problem

Five minor findings were left open after PR #841:

1. The cache guard in `read` (`apps/markdesk/src/document/DocumentPane.tsx`),
   `if (documents.get(path) === loading) documents.delete(path)`, has no test.
2. Removal of the window `focus` listener on unmount has no test. Note: the
   listener is no longer in `DocumentPane`. It is registered by
   `RefreshProvider` in `apps/markdesk/src/app/refresh.tsx`, so the test goes
   there.
3. `revalidate()` in `apps/markdesk/src/api/client.ts` (used by `document()` and
   `tree()`) repeats the network-error mapping and the ok/data check of `run()`
   to add one 304 branch.
4. Each window focus sends `GET /api/v1/entries/{id}` as well as the document
   check.
5. SAD_DESK_0015 in ADR-035 names two triggers in one entry.

## Decisions

- Item 4: keep the entry request. Close the item with this reason: `read` needs
  the entry to know `entry.location.file` before it can send the document
  request, and the document ETag covers only the file content and the graph's
  display IDs. The entry request detects an entry that was removed
  (`entry-not-found`, the "gone" state), moved to another file, or that gained
  an `origin`. A 304 on the document does not prove any of these. No code
  change.
- Item 5: split the entry. SAD_DESK_0015 keeps the selection-change trigger; a
  new SAD_DESK_0033 holds the window-focus trigger.

## Files to change

- `apps/markdesk/src/api/client.ts`: extract the shared part of `run()` and
  `revalidate()` into one private helper, for example
  `send<T>(call): Promise<Outcome<T>>` that maps a thrown error to
  `networkError(cause)`, and `dataOf<T>(outcome): T` that throws
  `errorFrom(outcome)` when `!response.ok || data === undefined`. `run()`
  becomes `dataOf(await send(call))`. `revalidate()` calls `send`, keeps only
  the 304 branch, then calls `dataOf`. Public `DeskClient` behaviour is
  unchanged.
- `apps/markdesk/src/document/DocumentPane.test.tsx`: one new test (below).
- `apps/markdesk/src/app/refresh.test.tsx` (new file): one new test (below).
- `docs/architecture/adr-035-markdesk.md`: split SAD_DESK_0015 (below).
- No change to `packages/markspec/desk/` or `schemas/desk-api.json`.

## Tests to add

1. `DocumentPane.test.tsx`, "keeps the newer render when an older failed
   document request settles last". Set up a fake client whose first
   `document(path)` call returns a deferred promise and whose second call
   resolves at once with render B and an ETag. Select an entry in that file
   (request 1 in flight), trigger a second read for the same path (window
   `focus`, or reselect), let request 2 resolve, then reject request 1 with a
   non-network `DeskError`. Then trigger a third read and assert that the
   `cached` argument passed to `document()` is render B with its ETag. This pins
   that the failure handler deletes the cache slot only when the slot still
   holds its own promise. The test must fail when the guard is replaced by an
   unconditional `documents.delete(path)` (verify by mutation once).
2. `app/refresh.test.tsx`, "stops counting window focus after unmount". Render
   `RefreshProvider` with a child that shows `useRefresh().revision`. Dispatch
   `focus`, assert revision 1. Unmount, spy on `globalThis.removeEventListener`
   or dispatch `focus` again and assert the refresh callback is not called (no
   React "update on unmounted component" path, spy count unchanged). Assert the
   removed listener is the same function that was added.
3. `api/client.test.ts`: no new test is required by the refactor, but run the
   existing 304, network-failure (`status` 0) and error-body tests for
   `document()`, `tree()` and one `run()`-based call unchanged. Add one test
   only if no existing test covers a network failure on `document()`.

## Alternatives considered

- Item 4, skip the entry request when the document answers 304: rejected. The
  entry request must run first to get the path, and a 304 does not prove the
  entry still exists in that file. Saving one local request per focus is not
  worth a stale view of a removed entry.
- Item 4, add a combined endpoint for entry plus document: rejected as new API
  surface for a loopback call with no measured cost.
- Item 5, keep one entry: rejected. The two triggers are verified by different
  tests and the single-responsibility rule forbids joining them with "and".
- Item 3, merge `run()` into `revalidate()` with an optional cache: rejected; it
  makes every plain call carry 304 handling it cannot receive.
- Item 2, test the listener through `DocumentPane`: rejected; `DocumentPane` no
  longer registers it, so the test would not pin the owning code.
