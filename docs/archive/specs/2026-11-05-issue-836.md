## ADR-035 change

Only item 9 changes an observable rule. Add one SAD entry to ADR-035 (next free
id `SAD_DESK_0034`): "The rendered chapter HTML shall carry at most one element
`id` per display ID; the first entry in source order keeps it." Leave `Id:`
absent and run `markspec fmt` then `markspec check` on the file. Items 1-8 and
10 need no ADR change.

## Alternatives considered

- Item 9, suffix the second anchor (`entry-X_0001-2`): rejected; a suffix is not
  addressable from the navigator, which knows only display IDs.
- Item 8, build one pipeline per server session: rejected; the known-ID set
  changes when the product is recompiled, so per-`CompileResult` caching is the
  correct lifetime.
- Item 7, drive commands through `tauri::test::mock_app`: possible but adds a
  dev feature and a heavier dependency for small gain; pure-function extraction
  matches the existing `assistant_settings` pattern.
- Item 4, unit test with an injected `realPath`: weaker; it does not prove
  `server.ts` calls the real resolver.
